- Context window - A context window is the amount of tokenised information a model can process within a request or active generation context. A language model does not have unlimited working memory, every model has a limit on how many tokens it can process at once. This is called context window. 
- Context may include - system instructions, current prompt, previous messages, uploaded document context, retrieved information, tool outputs, the model's generated response. All of these consume tokens.
- What happens when context window fills - Different applications may handle this differently - 
- possible strategies include - removing older conversations, summarising previous messages, retrieving only relevant sections, splitting the work into multiple requests
- visible conversation in the chat interface and the exact text in the model's context are not always identical. Every model has maximum context length.
- Vectorisation - vectorisation is the process of converting information(text, images, users, product or any information) into numerical vectors(array of numbers) Ex - [2,5], [3,8,7], [0.12, -3.5, 4.29] etc
-- It turns information into a form on which computers can perform mathematical operations.
- Embedding - An embedding is a learned numerical representation of an item that captures useful relationships with other items
- Dimensions in an embedding - Ex - King = [1.2, 0.4, ....] ; more dimension != more intelligence
- A model specific embedding may contain hundreds or thousands of values.
- Higher dimensions can capture more complex patterns but they also require more storage and computation.
  - Through training, the numerical representations are adjusted so that useful relationships become encoded in the vector space.
  - - Semantic similarity - it measures how close two pieces of texts are in meaning. An embedding based system can represent two queries in vector and discover that they are very close in meaning.
  - Embeddings allow systems to compare broader meaning rather than only matching identical words.
  - Cosine similarity - compares angle b/w two vectors, focuses more on direction than on absolute length
  - Token embeddings - This process replaces a meaningless token ID with a dense numerical vector. That vector becomes the model's initial representation of the token. Because the representaion may later change as the model process context.
  - the embedding tells the model which token is present, positional information helps tell the model where that token appears. The model needs both identity and order.
  - Token embedding vs Text embedding - token embedding helps a language model process a sequence internally. Text embeddings are often produced specifically for tasks such as search, retrieval, clustering, recommendations, classification, duplicate detection.
  - Static vs Contextual meaning - static assigns one single vector to the word.(not effective as same word has multiple meaning)
  - Polysemy - meaning depends on context as same word can have multiple meanings.
  - How modern LLMs handle context [Contextualisation] - In a transformer based language model, the token first recieves an initial token embedding. Then the model processes it together with the surrounding tokens. Through multiple layers, the representations become contextualised. It handles Polysemy.
  - Bias in embedding - human created data have a lot of flaws, as a result, embeddings can also encode undesirable associations

- Training of Neural Network - A neural n/w contains a huge collection of adjustable numbers, the parameters. During training, we repeatedly modify those parameters so that the model becomes better at a particular objective. For a neural network, learning becomes adjusting parameters so that future predictions becomes better.
- Do Parameters store knowledge - No, they are just random numbers but they have pattern hidden inside it that is learned through training data and now when you pass something into it, it does some calculation and gives correct output
- how is it related to training data - it is all the information passed to LLM on which it is trained.

- Back propagation - It calculates how changing each parameter would affect the loss. It starts from the error at the output and works backward. It calculates the sensitivity of the loss to each parameter. Mathematically these sensitivities are called gradients.
- Gradient - A gradient tells us which direction a parameter should move to change the loss and how sensitive the loss is to that parameter.
- Does back propagation fix the weights/parameters - it does not itself necessarily update the weights. It calculates gradient. Then an optimisation algorithm uses those gradients to update the parameters/weights.
- Gradient Descent - It is an iterative optimization algorithm used to minimize a function(like error or loss) by adjusting parameters in the opposite direction of the gradient. Core components - loss function, gradient, learning rate.
- Main types of gradient descent -
- Batch Gradient descent - uses the entire dataset to compute the gradient for each step; stable but slow on huge dataset. Challanges - Learning rate too small, Training takes forever.
- Stochastic Gradient descent(SGD) - Uses a single data point per step; fast but noisy and fluctuates. Challenges - Learning rate too large, the algorithm overshoots the minimum and fails to converge.
-  Mini batch gradient descent - Splits data into small subsets; strikes the best balance b/w speed and stability. Challenges - Local minima or saddle points. The system can get stuck when the slope is flat.
-  Forward Pass - It means one pass through neural n/w to generate one output by prediction

-  Sample Data -> Forward Pass -> Calculate Loss -> Back Propagation -> Optimiser/ Gradient descent -> Better Model
-  Self supervised learning - Model learns by itself; no manual intervention required; the next token becomes the target.
-  Some AI terms - 
   - Dataset - All training examples
   - Batch - A group of examples processed together; batch of examples -> calculate average loss -> update parameters
   - Training step - One optimisation update
   - Epoch - One pass through a training dataset
- training vs inference
  - Training - Input -> Forward pass -> prediction -> calculate loss -> back propagation -> update parameters
  - Inference - Input -> Forward pass -> prediction -> output
- Training changes the model; Inference just uses the model
- Generalisation - That ability to perform well on examples it did not directly memorise is called generalisation
- Good learning means discovering patterns that remains useful beyond the exact training examples.
- Overfitting - A model is overfitting when it becomes extremely good at its training examples but performs poorly on new examples. A useful model should generalise.
